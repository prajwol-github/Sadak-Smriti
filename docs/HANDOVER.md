## 3. How to verify everything yourself

Needs Docker running. All commands from the project root, in the Git Bash tool (the PowerShell tool has no `&&`).

```sh
pnpm db:up            # starts the local database on 127.0.0.1:5433 (container sadak-smriti-postgres-1)
pnpm db:migrate       # applies 0000..0010
pnpm db:places        # only needed on a fresh database; tests need districts
pnpm check            # lint + types + 470 unit tests
pnpm test:db          # 84 tests against the real database, as the `app` role, each rolled back
pnpm audit --prod     # must say "No known vulnerabilities found"
pnpm build
```

If you add or change a query: write it with `defineQuery`, list its file in `lib/db/queries/index.ts`, run `pnpm db:queries`, commit the generated `db/queries/**` (`pnpm check` fails otherwise).

To probe a built server: `pnpm exec next start -p 3111`, then `curl -s -o /dev/null -w "%{http_code}" -X POST http://127.0.0.1:3111/api/auth/two-factor/disable` must print 404, and `GET /api/auth/callback/google` must print 302 (it reached Better Auth). Stop the server afterwards (find it with `Get-NetTCPConnection -LocalPort 3111 -State Listen`; closing the shell does not stop it).

## 6. Gotchas that cost time here

- **Line endings.** Most source files are CRLF; `*.sql` and `*.sh` must stay LF (`.gitattributes`). A scripted find-and-replace with `\n` in its anchor silently matched nothing and two tests broke. Use the Edit tool, or check first, and re-run tests after any scripted edit.
- **Windows shells.** PowerShell 5.1 has no `&&`; use Git Bash for POSIX commands. `curl` in PowerShell is an alias; write `curl.exe`.
- **Next.js 16 is not the Next you know.** Read `node_modules/next/dist/docs/` before using a Next API (`AGENTS.md`). `proxy.ts` replaces middleware; `params` is a Promise; pages that read the session or `searchParams` must sit inside `<Suspense>`.
- **Roles.** The website's database role (`app`) cannot write `users.role`; only `pnpm users:role` (as `migrator`) makes reviewers or admins, and `staff_set_role` / `staff_set_ban` in the database enforce the account rules. Never bypass them from application code. Test permissions through Drizzle, not hand-written SQL (global lessons).
- **Better Auth** is only ever called as `auth().api.*` from server code. If you need a browser-facing endpoint, add it to `ALLOWED_GET_PATHS` after reading what it does in `node_modules/.pnpm/better-auth*/node_modules/better-auth/dist/`, and add a test.
- **Database tests** run as `app` inside a transaction that is always rolled back (`inRollback`). A failed statement aborts its transaction, so use one `inRollback` per statement that is expected to fail.
- **Retention is a promise.** If you add a column or table that holds a reporter's contact, an IP address or a hash of one, add its clean-up to `lib/maintenance/retention.ts` and a test, or SPEC 12.3 stops being true.
- **Secrets.** `BETTER_AUTH_SECRET` encrypts stored authenticator secrets and Google tokens; changing it signs everyone out and every staff member must set up the app again. `CONTACT_ENCRYPTION_KEY` loss makes reporter contacts unreadable. Neither belongs in backups or the repo.

## 7. Decisions made during this work (so nobody reopens them without a reason)

- Close the library's HTTP surface instead of trying to harden each of its endpoints: the app needs only Google's return address, and a closed door is easier to reason about than patched ones.
- Publishing from the editor is refused while a submission is pending (rather than requiring a news source): it keeps the staff-publish rule of ADR 0008 for staff-created crashes and removes only the shortcut around the queue.
- Rejected crashes stop owning their links; merged crashes still do (merging does not exist yet).
- Sessions keep an IP hash, and nothing at all when `IP_HASH_SECRET` is missing, rather than a raw address.
- `disableIpTracking` was **not** used: it would switch off Better Auth's own rate limiting.
- Web and worker run under systemd in the first deployment because the repository has no Dockerfile yet; the database stays in Docker.
