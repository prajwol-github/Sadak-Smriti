# db/: every SQL statement in one place

This folder holds all the SQL the project runs, so anyone can read and review it without knowing the code. Decision and reasons: [`docs/adr/0005-database-layout.md`](../docs/adr/0005-database-layout.md).

| Folder | What it holds | Written by |
|---|---|---|
| `migrations/` | Every change to the database structure, in order. Files run once each and are never edited after they have run anywhere | `pnpm db:generate` (from `lib/db/schema/*.ts`), or by hand for custom SQL (`pnpm exec drizzle-kit generate --custom --name=<what>`) |
| `queries/` | One file per query the app runs: what it is for, its parameters, and its exact SQL | **Generated** by `pnpm db:queries` from `lib/db/queries/*.ts`. Don't edit by hand |
| `seeds/` | Invented data for development. Never real people | By hand |

## Running the database locally

You need Docker.

```sh
cp .env.example .env.local   # then fill in IP_HASH_SECRET and CONTACT_ENCRYPTION_KEY (commands are in the file)
pnpm db:up                   # PostgreSQL 18 + PostGIS 3.6 on localhost:5433
pnpm db:migrate              # applies db/migrations/ and prints the PostGIS version
pnpm db:places:download     # names of provinces, districts, local units (boundaries come from pnpm map:download)
pnpm db:places               # loads 7 provinces, 77 districts, 753 local units (add --dry-run to only match names)
pnpm db:studio               # browse the data
pnpm db:reset                # deletes the local database and rebuilds it from the migrations
pnpm db:down                 # stops it
```

## Roles (SPEC 12.3)

Created once by `infra/db/init-roles.sh` when the database volume is new:

| Role | Used by | Rights |
|---|---|---|
| `migrator` | `pnpm db:migrate`, `pnpm users:role` | Owns the schema; the only role that can create or change tables |
| `app` | the website and the worker (`DATABASE_URL`) | Read and write rows; no DDL; `audit_log` is INSERT only; cannot change `users.role`, and new accounts are always contributors (migrations 0005, 0006) |
| `readonly` | exports and the public API (later) | Read only |

The extensions `postgis`, `pg_trgm` and `unaccent` need a superuser, so the same script installs them. Migration `0000_extensions.sql` only checks they exist.

## Adding or changing a query

1. Write it with `defineQuery` in the right file under `lib/db/queries/` (one file per area), with a `name` like `crashes/similar`, a `description` and invented `example` arguments.
2. If it is a new file, add it to `lib/db/queries/index.ts`.
3. Run `pnpm db:queries` and commit the new or changed `.sql` file with your code. `pnpm check` fails until you do.
4. Call it from app code with `run(query, args)` from `lib/db/queries/run.ts`, or inside `transaction(tx => …)` for writes.

Nothing outside `lib/db/` may import the database driver or Drizzle's runtime (`lib/db/boundary.test.ts`).

## Reading a query file

```sql
-- system/postgis-version                    ← the query's name
-- PostGIS version string. …                 ← what it is for
--
-- No parameters.                            ← or $1, $2 … with the example values used
--
-- Generated by `pnpm db:queries` from lib/db/queries/system.ts. Do not edit by hand.

select postgis_version() as version;
```

Parameters are always sent separately (`$1`, `$2`), never pasted into the SQL, so user input can't change a query. To try a query in `psql`, replace each `$n` with a value.

## Notes

- **How the snapshots are made:** Drizzle's mock client (`drizzle.mock()`) renders a query's SQL without connecting: `.toSQL()` for query builders, `.getQuery()` for raw `db.execute(sql…)`. Checked on 13 Nov 2026 with drizzle-orm 0.45.4.
- **Pinned versions:** drizzle-orm 0.45.4, drizzle-kit 0.31.11, postgres.js 3.4.9. postgres.js 4.0 (released 29 Oct 2026) was skipped until Drizzle states support for it; drizzle-orm 1.0 is still a release candidate.
- The PostGIS image also installs `postgis_topology`, `fuzzystrmatch` and `postgis_tiger_geocoder` in development. We don't use them; production installs only the three extensions above.
